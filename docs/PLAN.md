# ForgeCrew — 개발 계획

## 현재 상태

- 단계: **P1–P5 구현 진행 중. Worker 실행·게시·Launcher 전환 경로의 로컬 통합 검증 완료**.
- shared·dispatcher·worker 패키지에 중앙 YAML·SQLite·HTTP·활성화 구간·PR 리뷰·전체 재동기화 폴링과 두 Provider 어댑터를 구현했다. Worker의 setup/run/doctor, 독립 Heartbeat·Lease 감시, 격리 clone, 세션 재개, 완료 저널·게시 재조정, stop·steer를 연결했다. 실행 직전 중앙 권한·원본 댓글 검증과 시스템 라벨 동기화도 구현했다.
- `npm run check`: TypeScript 검사, Vitest 112개 테스트, tsdown 기반 세 패키지 JS 빌드, 빌드된 CLI·Dispatcher 프로세스 기동·SQLite·HTTP 인증·설정 재로드 smoke 검사를 통과했다. 로컬 검증 환경은 Linux / Node.js 24.22.1이다. Provider 프로세스와 GitHub 통합 Fixture를 실제 구독 실행과 구별한다. 사내 계정·실제 구독 모델 Turn·Windows 실제 사용자 환경·실제 사내 npm 업데이트·로그인 자동 시작 시험은 수행하지 않았다. Launcher 자식 프로세스 전환·롤백·중복 기동·종료, drain·패키지 격리 설치와 loopback npm 레지스트리의 실제 tarball 다운로드·자동 전환·불량 버전 rollback·ID/저널/작업 파일 보존을 로컬 시험으로 확인했다.
- Linux/Windows GitHub Actions 검사와 Dispatcher Dockerfile을 추가했다. 코드 `4ddc3c8`의 [CI 41451169932](https://github.com/neuwcodebox/forgecrew/actions/runs/41451169932)에서 Linux/Windows의 90개 테스트·빌드·배포 패키지 smoke와 Docker 검사가 모두 통과했다. Docker 검사는 비루트/읽기 전용 실행·원자적 YAML 교체·SQLite 재시작·정지 볼륨 백업/복원을 포함한다.
- 제품 정책과 배포 구조는 [SPEC](SPEC.md), 구체적인 동작 계약은 [TECH](TECH.md)를 기준으로 한다.
- 외부 환경에서 제공할 값은 GHES 호스트·테스트 저장소·PAT, Dispatcher 주소, 사내 npm 레지스트리·scope다. Worker는 기존 `gh` 및 Codex/Claude 구독 로그인을 사용한다.
- 기존 개발 코드가 있다면 먼저 구조와 동작을 확인한다. 문서와 파일 배치가 다르다는 이유로 전체를 재작성하지 않는다.
- 목표 일정은 설정하지 않는다. 단계별 완료는 동작·시험 증거로 판단한다.

## P1. 기존 구현 확인과 실제 런타임 계약 고정

**목표:** 현재 코드의 재사용 범위를 파악하고 사내 환경에서 사용할 정확한 실행·인증·프로토콜을 짧게 실증한다.

**관련 요구:** F1, F3, F6, F8–F12, N2, N4, N6.

**상태:** 진행 중.

- [x] 신규 저장소와 최종 하네스를 확인했다. 재사용할 기존 애플리케이션 코드는 없으며 문서·설정 예제를 보존했다.
- [x] Node.js 24 LTS, TypeScript, npm workspace, Hono, Drizzle/SQLite, Octokit, Vitest와 빌드 도구 버전을 고정하고 lockfile을 추가했다.
- [ ] Dispatcher PAT로 허용 저장소·댓글·PR·라벨 행위자·Write 권한을 읽고 시스템 라벨을 관리하는 작은 시험을 수행한다.
- [ ] Worker의 `gh`로 정확한 사내 호스트의 계정을 확인하고 자기 명의 댓글·Git 작업을 수행한다. Git 작성자·서명을 변경하지 않는지 확인한다.
- [ ] Codex App Server의 로그인·thread/turn·모델 카탈로그·effort·steer·interrupt·Auto Review를 실제 세션으로 시험한다.
- [ ] Claude 공식 실행 파일의 구독 로그인·JSON 스트림·명시적 세션 재개·Auto 모드·무인 질문 처리·interrupt 후 steer 재개를 시험한다.
- [x] Codex blocking 질문 보존·interrupt·종료와 Claude 무인 입력 경로를 프로세스 Fixture로 검증했다. 실제 구독 런타임 검증은 별도로 남아 있다.
- [x] 버전 명시 Launcher IPC, Worker 저널, 종료·서비스 연결과 독립적인 로컬 READY, 안정화 관찰과 전환 포인터 복구를 구현했다.
- [x] 중앙 YAML의 공통 스키마·명시적 비밀값 참조·Worker projection·revision 계약을 구현하고 예제 파싱·잘못된 후보 거절·원자적 활성화를 시험했다.
- [ ] Codex와 Claude에서 기존 세션 재개 시 중앙 지침 교체가 실제 적용되는 경로를 시험한다. Claude의 프롬프트 snapshot 옵션과 긴 지침 전달도 포함한다.

**완료 기준:** 두 엔진에서 구독 로그인으로 실제 실행이 가능하고 필수 제어·승인 경로가 확인된다. 지원 런타임 버전·명령·schema·시험 결과와 기존 코드 재사용 계획이 기록된다.

**근거:** `packages/shared/src/`, `packages/dispatcher/src/`, `packages/worker/src/`, `tests/`. 실제 설치된 Codex/Claude의 구독 실행·제어·자동 검토가 검증되지 않아 P1 전체는 완료하지 않았다.

## P2. 단일 Worker의 GitHub 대화 종단간 실행

**목표:** 라벨을 지정한 Issue/PR에서 요청·응답·후속 대화가 이어진다.

**관련 요구:** F1–F3, F6, F8–F10, F12, N1, N3, N4, N6.

**선행:** P1의 GitHub 계약과 한 엔진의 실행 경로.

**상태:** 진행 중.

- [x] Docker Dispatcher·영속 SQLite·migration·health 경로를 구현하고 이미지 기동·재시작·백업 복원을 CI에서 확인했다.
- [x] 저장소·조회 종류별 증분 폴링·전체 재동기화·페이지 순회·중복 제거·활성화 구간과 최초 본문을 구현하고 Fixture로 확인했다.
- [x] 권한·모델/effort 라벨 해석·충돌 보류와 실행 직전 원본 확인을 구현하고 계약 시험을 통과했다.
- [x] Session/Input/Turn/Attempt·FIFO·stop·steer·질문 후 새 Turn을 연결하고 저장소·Provider·Worker 통합 Fixture로 확인했다.
- [x] Worker의 로컬 저널·완료 보고·Delivery 게시 경로를 연결하고 완료 ACK·게시 응답 유실을 통합 Fixture로 검증했다. 실제 `gh` 계정으로 게시하는 시험은 남아 있다.
- [x] 계정·게시 ID·Delivery 표식·본문 hash로 자동 출력만 제외하며 동일 계정의 직접 작성 댓글은 입력으로 수집하는 시험을 통과했다.
- [x] YAML 재로드·인증된 projection·캐시·실행 스냅샷 검증을 Worker에 연결했다. 새 지침을 다음 Turn에 전달하고 진행 중 스냅샷을 보존하는 통합 Fixture를 통과했다.
- [ ] 중앙 공통 지침과 저장소 지침을 함께 적용하고 답변만 하는 요청도 정상 완료한다.
- [x] AI/런타임 출처·본문 고정·Delivery별 표식·분할 게시를 구현하고 계약 시험을 통과했다. 표시 문구와 자동 출력 식별은 독립적이다.

**완료 기준:** 독립 Issue/PR 세션에서 라벨과 일반 댓글만으로 실제 대화가 이어진다. 폴링 반복으로 같은 작업이 다시 실행되지 않는다. 질문을 남긴 Turn은 슬롯을 반환한다. 제어 명령은 정확한 Attempt에만 적용된다.

**근거:** 아직 없음.

## P3. 분산 배정·다중 세션·장애 복구

**목표:** 여러 PC의 Worker가 용량 안에서 실행하고 장애 후 논리적으로 이어간다.

**관련 요구:** F2–F7, F10, F12, N1–N4.

**선행:** P2의 기본 대화·큐·게시 경로.

**상태:** 진행 중. 분산 배정·Lease·복구의 로컬 계약 구현, 실제 여러 PC 장애 시험 대기.

- [x] Worker ID·플랫폼 인증·로컬 GitHub 접근 저장소·모델 목록 보고를 연결하고 등록·배정 계약을 검증했다.
- [x] 숫자 버전·최신 모델·접근·effort·Auto Review·슬롯 배정을 시험했다. 최신 모델 보유 Worker가 바쁠 때 구버전으로 낮추지 않는다.
- [x] 원자적 Claim·Lease·generation과 실행/설정 조회에 독립적인 Heartbeat·갱신·제어 처리를 구현했다. 현재 제어 전송은 Heartbeat 응답을 사용한다.
- [x] 세션별 실행을 분리하고 같은 브랜치의 독립 clone 두 개로 dirty 파일·미추적 파일·Git 사용자/서명 설정 보존을 로컬 Git 시험에서 확인했다. 사내 gh clone은 미검증이다.
- [ ] 네트워크 단절·Dispatcher 재시작·Provider 종료·Worker 충돌·PC 절전/복귀를 구별한다.
- [ ] Lease 만료 전 중단·자식 프로세스 정리와 재배정 유예 관계를 실제 Windows/Linux에서 시험한다.
- [x] 완료 ACK 유실·게시 응답 유실·다른 계정 Worker의 Delivery만 복구를 통합 Fixture로 확인했다. 완료된 Provider 작업을 반복하지 않는다.
- [x] dirty workspace 보존과 새 generation 완료 뒤 이전 Worker의 늦은 결과를 rejected-results에 보존하는 시험을 통과했다. 늦은 결과가 Delivery를 덮어쓰지 않는다.
- [ ] 설정 전송 중단·초기 캐시 없음·설정 revision 경합·Lease 정책 변경 중의 신구 Attempt 동시 존재를 시험한다.

**완료 기준:** 2개 이상의 Worker와 한 Worker 안의 2개 이상의 세션에서 용량·격리·권한 계약이 유지된다. Dispatcher 단절에 Worker가 죽지 않는다. 장애 복구가 완료 작업 재실행과 혼동되지 않는다.

**근거:** 아직 없음.

## P4. 두 엔진의 기능 일관성과 모델 설정 완성

**목표:** Codex와 Claude 각각에서 합의한 사용자 흐름과 자동 검토가 동작한다.

**관련 요구:** F3, F6, F8, F9, F12, N4, N6.

**선행:** P1의 런타임 실증, P2–P3의 실행 경로.

**상태:** 진행 중. 두 Provider 프로세스 계약 구현, 실제 구독 실행·자동 검토 시험 대기.

- [x] 엔진 단일/동시 활성화와 상태 격리를 구현했다. 한 엔진의 사용량 제한 후 다른 엔진의 Turn이 정상 실행되는 통합 Fixture를 통과했다. 실제 인증 만료 시험은 남아 있다.
- [ ] 새 모델 발견·계열 변경·effort 변경·미지원 조합·사용량 제한·인증 만료를 처리한다.
- [ ] 실제 적용 모델·effort·Auto 모드가 요청과 일치하는지 검증하고 런타임의 조용한 fallback을 감지한다.
- [ ] Codex 직접 steer와 Claude interrupt/resume의 차이를 표시하면서 같은 논리 작업을 유지한다.
- [ ] 네이티브 질문 요청·최종 자연어 질문·권한 승인 요청을 구별한다.
- [ ] 기존 사용자 설정·저장소 지침·구독 인증을 유지하고 직접 모델 API 결제를 요구하지 않는지 확인한다.
- [ ] 두 엔진 모두 새 지침의 다음 Turn 적용과 진행 중 Turn의 기존 지침 유지를 시험한다. 지침만 바뀔 때 패키지 갱신을 요구하지 않는다.

**완료 기준:** 두 엔진 각각에서 요청·후속 대화·모델/effort·질문·stop·steer·Auto Review가 실제로 시험된다. 필수 동작은 구현 또는 명시된 동등 대체를 충족해야 한다. “미지원이라고 표시함”만으로 완료하지 않는다.

**근거:** 아직 없음.

## P5. 사내 npm 설치·무인 업데이트·Docker 배포

**목표:** 설치 이후 릴리스마다 사용자에게 종료·재설치·재실행을 요구하지 않는다.

**관련 요구:** F7, F11, F12, N1–N5.

**선행:** 초기 Launcher/저널 구조와 안정된 실행 계약. 설치 준비 작업은 P2–P4와 병행한다.

**상태:** 진행 중. 로컬 Launcher·업데이트 경로 구현, 실제 OS 로그인·사내 npm 배포 검증 대기.

- [ ] 사내 npm에 production Worker 패키지를 게시하고 깨끗한 PC에서 Node.js 외 개발 도구체인 없이 설치한다.
- [x] setup·start·stop·status·doctor와 중복 기동 방지를 구현하고 프로세스 Fixture·배포 패키지 smoke로 확인했다. Linux 사용자 서비스·Windows 로그온 작업의 등록/해제 어댑터를 추가했다. 실제 로그인 자동 시작은 미검증이다.
- [x] 버전별 staging 설치·npm lock 무결성·Node/프로토콜·상태 schema 확인과 drain·한도 중단 후 Turn 복구를 구현했다. npm 설치 계약 Fixture와 실제 tarball 격리 설치를 구분해 검증했다.
- [x] Launcher 전환 포인터·이전 포인터 복구·READY·안정화·lastKnownGood·롤백·cooldown을 자식 프로세스 시험으로 확인했다.
- [ ] npm/Dispatcher 불통, 설치 실패, 새 버전 실행 오류, 포인터 교체 중 충돌, 상태 schema 변경을 구별한다.
- [x] 실제 npm tarball의 자동 전환·불량 버전 rollback 후 Worker ID·설정 캐시·인증 설정·작업 파일·미전달 결과가 유지되는 loopback 시험을 통과했다. 다른 state schema는 설치 전에 거절하며 사내 배포·실제 OS 로그인 시험은 남아 있다.
- [ ] 중앙 YAML의 마운트 파일 교체·잘못된 수정·재시작 필요 항목·Secret 비노출을 시험하고 설정 적용 상태를 진단할 수 있게 한다.

## 바로 이어갈 작업

**구현된 경로의 실제 환경 검증과 아직 시험하지 않은 장애 조합을 진행한다.** PR 리뷰 본문·활성화 구간 보정·시스템 라벨 동기화·실행 직전 권한/원본 확인, Launcher·업데이트·자동 시작 어댑터는 구현되어 있다. 이를 재구현하지 말고 다음 항목부터 확인한다.

1. GHES 테스트 저장소와 Worker의 기존 계정으로 요청·후속 대화·Write 권한 변경·댓글 편집/삭제·실제 게시를 시험한다. Codex/Claude 구독 모델의 카탈로그·실제 Turn·Auto Review·stop·steer·질문 종료와 중앙/저장소 지침 적용을 확인한다. 현재 Provider 결과는 프로세스 Fixture이며 실제 모델 Turn 검증은 아니다.
2. 로컬 통합 시험의 두 Worker 경쟁·세션별 stop·계정 간 Delivery 복구·stale 결과와 실제 Git clone의 dirty 상태 보존을 기준으로, 실제 PC의 절전/복귀·자식 트리 종료·원격 Git 상태와 설정 경합의 남은 조합을 시험한다.
3. 사내 registry·정확한 package/scope를 확정해 실제 릴리스 감지·설치·drain·전환·rollback을 시험한다. Windows/Linux 로그인 자동 시작·로그아웃·자식 프로세스 트리 종료·기존 사용자 환경 유지도 실제 OS에서 확인한다.

검증에 필요한 외부 값은 현재 상태에 정리했다. 실제 사내 값이나 계정이 없는 시험은 완료 표시하지 않는다. 최근 배포 검증·판단은 [Launcher 기록](history/2026-11-02-launcher-updates.md), Provider·입력·게시 계약은 [런타임 기록](history/2026-11-02-runtime-contracts.md)에서 이어 읽는다.

문서의 개발 순서는 제품 기능의 우선순위이며 실사용 완료 범위를 줄이는 기준이 아니다. 구현 중 필수 동작을 바꾸어야 할 이유가 발견되면 영향과 대안을 먼저 제시하고, 현재 동작 문서와 계획을 함께 갱신한다.
