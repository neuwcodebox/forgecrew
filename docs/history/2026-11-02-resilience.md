# 후속 리팩토링과 강건성 검토

## 범위

추가 분할을 늘리지 않고 종료·완료 보고·동시 갱신·게시 순서를 검토했다. 기존 모듈 3개 안에서 상태 처리와 중복 조건을 정리했다. SPEC의 요구사항·AGENTS 지침·외부 HTTP/파일/DB schema는 변경하지 않았다. 관련 요구는 F5, F7, F10, F12, N3이며 P2–P5의 로컬 복구·게시 검증에 해당한다.

## 재현과 수정

| 문제 | 수정 |
|---|---|
| 이미 중단 중인 Attempt를 다시 중단하면 즉시 반환해 shutdown이 실행 종료 전에 끝날 수 있었다. | 중단을 중복 전송하지 않고 기존 작업의 종료를 기다린다. 정리 실패가 확인되면 중단 호출자에게 종료 불확실 오류를 전달한다. |
| terminal 결과를 받은 뒤 Provider의 `close()`가 실패하면 완료 저널·보고가 생략되어 나중에 작업이 재실행될 수 있었다. | 정리 오류를 별도 기록하고 받은 결과의 저널·완료 보고는 진행한다. 중단된 실행의 종료가 불확실한 경우에는 즉시 release하지 않고 기존 Lease·유예에 따른 회수를 기다린다. |
| 오래 걸린 모델 조회가 실행 중 감지한 인증/사용량 제한을 `ready`로 되돌리거나 더 최근 카탈로그를 덮어썼다. | 갱신 후보를 계정·저장소·모델 단위로 모아 원자적으로 반영한다. 갱신 순서와 차단 변경을 revision으로 확인해 오래된 후보를 폐기한다. |
| 긴 답변을 분할했을 때 앞부분이 다른 Worker에서 게시 중이어도 뒤의 Delivery를 Claim할 수 있었다. | 세션의 가장 앞선 미게시 Delivery만 Claim·재조정한다. `hasPending`과 Claim이 같은 SQL 조건을 사용하고 다른 세션의 진행은 막지 않는다. |

## 검증

수정 전 코드에서 회귀 시험 7개가 실패하는 것을 확인한 뒤 수정했다. 시험은 완료 결과 보존, 기존 interrupt 완료 대기, 종료 불확실 시 소유권 미해제, 차단 상태 보존, 늦은 카탈로그 응답, 세션별 분할 순서·세션 간 독립 진행, 만료된 앞부분의 우선 재조정을 검증한다. Promise gate와 이벤트 루프 경계를 사용하며 실행 속도에 따른 고정 대기에 의존하지 않는다.

로컬 Linux / Node.js 24.22.1에서 `npm run check`의 포맷·타입·미사용 코드 검사, 138개 테스트, 세 패키지 빌드, Dispatcher·packed Worker 설치·loopback npm 자동 전환/rollback smoke가 통과했다.

코드 커밋: `8f24a963c22ae89c5ff2518eed3e7ada87039b9e`. [CI 41468036109](https://github.com/neuwcodebox/forgecrew/actions/runs/41468036109)에서 Linux·Windows의 전체 `check`와 Docker 검사가 모두 통과했다.

실제 GHES·구독 모델·회사 npm·사용자 OS 로그인/절전 수용 검증의 기존 미완료 범위는 유지한다.
