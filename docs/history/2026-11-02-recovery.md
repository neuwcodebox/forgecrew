# 분산 복구와 모델 가용성 검증

관련 요구는 F4–F7·F10·N3·N4·N6, 단계는 P2–P4다.

신선한 카탈로그의 최신 모델을 먼저 결정하고 가용 상태를 별도로 확인한다. 최신 모델이 인증·사용량 제한·일시 불가 상태일 때 구버전 Worker를 조용히 선택하던 경로를 차단했다. 모델 갱신이 실패해도 직전 카탈로그를 상태와 함께 보존한다. Codex의 native usage/rate limit과 unauthorized, Claude assistant의 인증·rate limit 오류를 일반 AI 답변 실패와 구별한다. 해당 Turn은 결과를 소비하지 않고 recovering으로 돌리고 엔진 상태를 보고한다. 카탈로그가 정상화되면 같은 Turn·고정 모델로 재개한다.

두 Worker 통합 Fixture로 경쟁 Claim에서 단일 소유권, 두 세션 병렬 실행과 stop 격리, 완료 ACK 유실 뒤 다른 계정이 게시만 수행하는 경로, 원 계정 게시 응답 유실의 재조정, 새 generation 완료 뒤 이전 결과 거절·로컬 보존을 확인했다. 고정 대기 대신 Provider 시작·완료 이벤트와 상태 조건을 사용한다.

실제 로컬 Git 저장소를 만들고 gh clone 경계만 로컬 origin으로 대체해 같은 브랜치의 독립 clone 두 개를 시험했다. 기존 checkout을 재사용할 때 dirty·미추적 파일과 로컬 Git 사용자·서명 설정이 유지되고, 다른 세션 파일과 섞이지 않는다. 관리 디렉터리 밖을 가리키는 symlink/junction도 거절한다.

`npm run check`의 103개 시험·빌드·Dispatcher/배포 패키지 smoke가 Linux 로컬에서 통과했다. 사내 접속 변수와 gh·Codex/Claude 전역 실행 파일이 현재 환경에는 없다. 실제 GHES·구독 모델 Turn·사내 npm·OS 로그인 수용 시험의 대체 증거로 삼지 않는다.

## 게시 소유권과 취소 경계

Delivery에도 발급 TTL을 저장하고 Heartbeat에서 갱신한다. 갱신 실패/만료 또는 Worker 종료 때 진행 중 gh 요청을 취소하며 새 POST 전에 소유권·로컬 계정을 확인한다. 게시 성공 뒤 ACK 유실의 동일 receipt는 Lease 만료 뒤에도 멱등 처리하고 서로 다른 댓글 ID로 덮어쓰지 못하게 한다. schema migration 2는 기존 Delivery 행을 보존하면서 TTL 열을 추가한다.

GitHub 컨텍스트 조회·clone·PR checkout에도 Attempt 취소 신호를 전달한다. Provider가 시작되기 전 drain/Lease 중단이 걸리면 gh 프로세스가 끝난 뒤 Turn을 복구 대상으로 반환한다. GitHub 조회 장애는 요청을 AI 실패로 소비하지 않고 해당 저장소 접근 상태를 재확인할 때까지 보류한다.

게시 중 Heartbeat 갱신·다른 Worker의 조기 Claim 거절, shutdown/Lease 상실 중 POST 취소 후 다른 Worker의 게시만 복구, 로컬 계정 전환 후 재보고, GitHub 준비 중 drain, 한 엔진의 quota 장애와 다른 엔진의 실행을 검증했다. 기존 Windows Git 설정의 CRLF checkout은 유효한 결과이므로 fixture의 원본 텍스트 비교만 줄바꿈을 정규화했다.
